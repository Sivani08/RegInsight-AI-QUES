# Chatbot implementation decisions

Existing design is the locked visual reference: teal inspection workspace, white evidence panels, Segoe UI. Refero's bundled typography guide supplies the neutral work-tool reading hierarchy. User explicitly requests strong bold chat text. Answer and question body use 17 px with 650/750 weight, 1.7–1.75 line height; headings use 750 weight, supporting provenance remains smaller. Local model readiness, sources, calculation evidence, elapsed times and stop control are visible. Graph analytics remains a separate tab.

The second agent is RegInsightChatAgent. It retrieves a compact curated project knowledge corpus and uses DashboardInsights for numerical portfolio questions. The planner owns the SQL; the model cannot execute code, SQL, web requests or change data. Current filters and persisted dashboard context feed the existing analytics service. Only previous user questions are supplied as conversational context; generated answers are not recycled as evidence.

Initial deployment model: Qwen3 1.7B Q4_K_M via local Ollama, already installed on the approximately 12 GB RAM computer. This is a resource-conscious starting point, not a claim of global benchmark superiority. Apache-2.0 model reference: https://ollama.com/library/qwen3:1.7b . Ollama chat API: https://docs.ollama.com/api/chat . Configuration file format: https://docs.ollama.com/modelfile . A larger model should replace it only after evaluation on expert-reviewed RegInsight questions and latency measurement on the deployment machine.

`reginsight-chat:qwen3-1.7b` adds a RegInsight system prompt and generation settings to existing base weights. There is no fine-tuning or training claim. The user supplied no expert-reviewed QA training/holdout corpus. Retrieval keeps dataset facts current without pretending the model memorized the database.

NDJSON sends source evidence before generation completes. One generation is allowed at a time; busy requests receive an explicit evidence-only response rather than joining an unbounded queue. The generation timeout is 45 seconds, context is bounded, thinking output is disabled, and the model stays warm for 10 minutes. Client cancellation closes the stream and cancels the local HTTP request. Generated text is displayed only after schema, citation-ID and numeric-token checks. These checks do not establish semantic truth. The UI states the limit and shows sources for human verification. No model response is cached across users.

Setup: with Ollama running and qwen3:1.7b installed, run `.venv/Scripts/python.exe scripts/setup_chatbot.py`. Then use the normal launcher. Chat uses its own CHAT_MODEL and CHAT_OLLAMA_URL settings; it does not change rules-based batch classification or enable remote providers.

For a panel demonstration: open Portfolio → AI chatbot; ask “What does OAI mean?”, then “What stands out in this dashboard?”; expand a source, show the calculated result and measured latency, switch to Graph analytics, and explain the difference between model narration and authoritative calculation. An evidence-only fallback must not be presented as a live LLM success.

Numerical-answer hardening (29 September): live portfolio tests showed that copying the right number does not guarantee a correct denominator explanation. Dashboard prompts now project only requested metrics and compact scope, rather than full nested site-risk records. The backend constructs complete numerical statements; a request-specific output schema limits the local model to selecting one of those statements or their combined summary. Backend validation independently requires an exact permitted answer and citation D1. General methodology answers still use ordinary retrieval-grounded generation and need human review.
